==============================================================================
一、这是什么
==============================================================================

一个纯本地运行的安卓小工具：把任意一段文字编成「吾苍耳冯福」这五个字组成的
字符串，也能把它还原回来。做出来是给朋友之间发暗号、玩梗用的，不是加密工具。

一句话原理：一个字在 UTF-8 里是 1～4 个字节，每个字节是 0～255；把每个字节
写成四位五进制（0000～4444），再把每一位换成五个字，就得到密文。所以密文长度
永远是原文【字节数 × 4】，四个符号正好一个字节，十二个符号正好一个汉字。

    「苍」→ UTF-8 = E8 8B 8D → 232 139 141
           → 苍福苍耳 / 苍吾耳福 / 苍吾冯苍

全部在本机完成：不联网、不注册、不上传。卸载之后，存根和册号一起消失。


==============================================================================
二、编码规格（可以照着手工实现）
==============================================================================

字母表（位值）：

    0 = 吾      1 = 苍      2 = 耳      3 = 冯      4 = 福

编码：
    1. 文本按 UTF-8 取字节序列 b1 b2 ... bn
    2. 每个 b 拆成四位五进制 d1 d2 d3 d4（高位在前），
       满足 b = d1*125 + d2*25 + d3*5 + d4
    3. 每位换成对应汉字，按顺序连起来，不加分隔符

解码：
    1. 去掉所有空白字符（空格、换行、全角空格都算）
    2. 字符必须全部在「吾苍耳冯福」里；出现别的字就报错并给出是第几个
    3. 字符个数必须是 4 的倍数
    4. 每四位算回一个字节；算出来大于 255 就报错并给出是第几组
    5. 字节序列必须是合法的 UTF-8，否则报错（不会悄悄丢字）

解码报错的四种情况（应用里就是这四句话）：

    第 5 个字符「a」不在吾苍耳冯福里。
    有效字符共 5 个，不是 4 的倍数，密文不完整。
    第 1 组超出字节范围，无法还原。
    （以及「还原结果不是合法的 UTF-8 文本」）

注意：这是可逆编码，不是加密。没有密钥、没有密码学强度，任何人拿到密文都能
还原——请在「使用须知」那五条的前提下使用。

    看起来像密文（全是这五个字且长度是 4 的倍数）就自动还原，否则自动编码。

    页眉「字号 中」，点一下按 中 → 大 → 小 循环，记在本地。全应用所有字号

    页眉「夜间版 / 日间版」，纸色和墨色互换。记在本地。

    NO.00N、类型（编码 / 还原）、时间、明文一行、密文一行，以及
    「载入」「复制」「下载」「删除」四个动作。

        类型：编码
        时间：2026-11-08 16:57

        明文：晚上八点老地方，别迟到。

        密文：苍福苍吾 苍苍吾冯 ...

撤销（1.3.0 新增）
    「清空」「交换」「删除一张存根」「清空存根」之后，状态行右边会出现
    「撤销」，六秒内点它可以还原到操作前的样子。

使用须知

册号
    页眉右上角「册号 30884」，第一次打开随机生成一个五位数存在本地，之后

      + 册号 / 版本 / 夜间版 / 字号

五、怎么构建（不用 Android Studio）
==============================================================================

全部用手工工具链，不上 Gradle。需要的四样东西：

    · JDK 17（只用到 javac 和 java）
    · Android SDK build-tools 34.0.0（提供 aapt2、zipalign、apksigner、d8.jar）
    · Android platform 34 的 android.jar
    · 本仓库的 app/ 目录（清单、代码、资源、assets）

在仓库根目录下：

    powershell -ExecutionPolicy Bypass -File build.ps1

它依次做六步：aapt2 compile 资源 → aapt2 link 打包（含 -A app\assets）
→ javac 编译 Java → d8 转 dex → 组装未对齐 APK 并修正 asset 路径 → zipalign
对齐 + apksigner 签名（debug 密钥，v1/v2/v3 全签）。

六个坑（都踩过，都写进脚本了）：

    1. 工作区路径含中文时，aapt2 / zipalign 这些原生程序按 ANSI 读参数会
       报 ENOENT。脚本里先 Set-Location 到脚本目录，全用相对 ASCII 路径。
    2. aapt2 link 的 -R 是 overlay 语义，编译产物要作为位置参数传，不能用 -R，
       否则报 "does not override an existing resource"。
    3. 无 BOM 的 UTF-8 .ps1 会被 Windows PowerShell 5.1 按 GBK 解码，中文字节
       吃掉引号导致解析错误。脚本保持纯 ASCII，汉字用 [char]0x543E 这种写法。
    4. aapt2 在 Windows 上写 asset 条目名用的是反斜杠（assets\fonts\x.otf），
       Android 的 AssetManager 按 / 查找会 404，字体静默回退。脚本在打包后
       打开 zip 把反斜杠条目改名成 /，再对齐、签名。
    5. 构建脚本的退出码可能是 1：javac 的 deprecation 提示走 stderr，被
       PowerShell 5.1 当成 NativeCommandError。构建本身是成功的。
    6. 资源里只有一个 Activity，launchMode 必须是 singleTop，否则从别的应用
       分享进来时会新开一个实例，onNewIntent 不会触发。

==============================================================================
1. WHAT IT IS
==============================================================================

A small offline Android tool that turns any text into a string made only of the
five characters 吾 苍 耳 冯 福, and turns it back. It is meant for sending coded
notes to friends, not for protecting secrets.

How it works, in one line: a character is 1-4 bytes in UTF-8, each byte is
0-255, and every byte is written as four base-5 digits (0000-4444). Each digit
is mapped to one of the five characters. So the cipher is always exactly
4 x (number of UTF-8 bytes) characters long: four symbols per byte, twelve
symbols per Chinese character.

    "苍" -> UTF-8 = E8 8B 8D -> 232 139 141
         -> 苍福苍耳 / 苍吾耳福 / 苍吾冯苍

Everything runs on the device: no network, no account, no upload. Uninstalling
takes the saved stubs and the book number with it.


==============================================================================
2. THE CODE (you can reimplement it by hand)
==============================================================================

Alphabet (digit values):

    0 = 吾    1 = 苍    2 = 耳    3 = 冯    4 = 福

Encode:
    1. take the UTF-8 bytes b1 b2 ... bn of the text
    2. split each byte into four base-5 digits d1..d4 (most significant first),
       where b = d1*125 + d2*25 + d3*5 + d4
    3. map each digit to its character and concatenate, with no separator

Decode:
    1. strip all whitespace
    2. every character must be one of the five; anything else is an error that
       names the offending position
    3. the character count must be a multiple of 4
    4. every group of four must evaluate to 0-255, otherwise an error names the
       group
    5. the resulting bytes must be valid UTF-8, otherwise an error is raised
       (nothing is ever dropped silently)

This is a reversible encoding, not encryption. There is no key and no
cryptographic strength; anybody holding the cipher can restore the text.

==============================================================================
4. DESIGN
==============================================================================

The design world is a pocket one-time pad: paper, ink and vermilion; serif type
throughout; a dense grid; no motion at all - switching and results are instant.

    - Header: the title, a subtitle, then book number / version / night mode /
      text size.
    - Specimen strip: the five characters as five cells, each labelled with its
      digit (0-4); tapping a cell inserts that character.
    - Input block: labelled 明文 or 密文, with "12 字 · 36 字节" on the right.
    - Buttons: filled ink "编 码" is primary, outlined "还 原" is secondary.
    - Result: the cipher is laid out four characters per group, like the ruled
      squares of a real codebook.
    - Bottom bar: encoder / notice / stubs, instant switching, no sliding
      indicator.

On a tablet the book opens as a two-page spread - write on the left page, read
the cipher on the right, with a 1px rule down the middle as the spine. Phones
keep a single column.

Three colours only: paper, ink, vermilion. No gradients, no shadows, no rounded
cards - hierarchy comes from hairlines and type size, not from elevation.


==============================================================================
5. BUILDING IT (without Android Studio)
==============================================================================

No Gradle. The build is aapt2 -> javac -> d8 -> zipalign -> apksigner, driven by
a PowerShell script. You need JDK 17, build-tools 34.0.0, platform android-34,
and this app/ directory.

    powershell -ExecutionPolicy Bypass -File build.ps1

Six traps, all handled in the script:

    1. Native SDK tools (aapt2, zipalign) read arguments in the ANSI codepage,
       so absolute paths containing non-ASCII characters fail with ENOENT. The
       script cd's to its own folder and uses relative ASCII paths only.
    2. aapt2 link's -R is overlay semantics; compiled resources must be passed
       positionally or you get "does not override an existing resource".
    3. A BOM-less UTF-8 .ps1 is decoded as GBK by Windows PowerShell 5.1 and
       Chinese bytes eat the quotes. Keep the script pure ASCII and use
       [char]0x543E for glyphs.
    4. aapt2 names asset entries with backslashes on Windows
       (assets\fonts\x.otf); Android's AssetManager looks them up with "/" and
       silently falls back. The script renames those entries inside the zip
       before aligning and signing.
    5. The script may exit 1 because javac writes deprecation notes to stderr
       and PowerShell 5.1 treats that as NativeCommandError. The build is fine.
    6. The single activity uses launchMode="singleTop"; otherwise an incoming
       share starts a second instance and onNewIntent never fires.

The fonts are subsets: the page's own characters + ASCII + the 3755 most common
GB2312 characters, cut with fonttools pyftsubset. That is why each weight is
1.1 MB instead of the original 11 MB.

The injected shim (1) routes navigator.clipboard.writeText to the real Android
clipboard, because the built-in one is unreliable for file:// documents inside a
WebView, and (2) maps window.close to Activity.finish(). The bridge object is
called AndroidShell and exposes five methods: copyToClipboard, closeApp,
saveText, shareText, takeShared.

    _shot.js     prepares a scene by location.hash (editor/ink/announce/history/
                 decode/error/consent) and reports overflow numbers
    _smoke.js    regression: consent, six round-trips, three error messages,
                 theme, stubs
    _measure.js  layout measurement: block widths, horizontal overflow, scroll


==============================================================================
8. KNOWN LIMITS
==============================================================================

    - Never run on a real device: the save dialog, the share sheet, the
      clipboard and rotation are verified statically and in headless Chrome
      only.
    - The cipher is 4x the original byte length, so a long note becomes a very
      long string that a chat app may refuse. There is no chunking yet.
    - Stubs live only on the device; changing phones or clearing data loses
      them, and there is no export-all.
    - There is no checksum: a single mistyped character can decode into wrong
      but plausible text instead of raising an error.
    - The five-character code is public and reversible. It is not encryption.
